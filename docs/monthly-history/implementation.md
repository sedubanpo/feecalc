# 월별 수강료 히스토리 구현 기록

기준일: 2026-10-21. 이 문서는 구현된 월별 히스토리 화면과 배포 후보의 검증 범위를 기록한다. 기존 `PRODUCT.md`·`DESIGN.md`를 대체하지 않으며, 아래 화면별 치수를 전역 디자인 규칙으로 확장하지 않는다. 작성 시점의 상태는 **구현·검증·운영 배포 확인 완료**다.

## 사용 흐름과 화면

직원이 학생의 학교·학년을 확인해 선택하고 조회 범위의 마지막 달을 정하면 최근 3개월의 수업·정산 흐름을 본다. 상단 월 카드를 선택하면 이미 받은 자료 안에서 달력이 바뀐다. 선택 월은 카드의 `선택` 문구·전체 외곽선과 별도 학생·월 문맥에 함께 표시한다.

데스크톱은 넓은 월간 달력 왼쪽, 정산 설명 오른쪽이다. 과목별 합계를 누르면 해당 수업은 유지하고 다른 과목의 항목을 옅게 표시한다. 합계나 수업 건수는 바꾸지 않는다. 수업을 누르면 날짜·반명·강사·시간·출결·적용 수업료를 확인한다. 납부·환불은 펼쳐 보는 원장에 표시한다. 새 화면에서 기존 계산 화면으로 돌아갈 수 있다.

## 금액의 출처와 의미

```text
정산 잔액 = 전월에서 넘어온 시작 잔액 + 이번 달 수업료 − 순수납액
순수납액 = 납부 − 환불 (기존 정산 모델의 유효한 정정 포함)
다음 달 별도 조정 = 다음 달에 저장된 시작 잔액 − 이번 달 정산 잔액
```

양수 잔액은 다음 달 추가 반영, 음수 잔액은 다음 달 차감으로 설명한다. 납부 원장은 정산에 미치는 부호로 표시하므로 납부는 음수, 환불은 양수다. 환불이 납부보다 크면 순수납액은 음수가 될 수 있다. 소수 금액은 보존하고 계산 결과는 소수 둘째 자리로 반올림한다.

- 수업 상세는 기존 `readFeeCalcProgress`, 수납 상세는 `readFeeCalcPayments`를 재사용한다. 수업료·자동 잔액은 기존 `readBalanceHistory`·`projectCalculatorBalanceMonth`·청구 모델을 따른다. 화면의 표시 단가로 원본 청구액을 새로 계산하지 않는다.
- 학생별 `intranetFinancials`의 저장된 월 시작 잔액과 순수납 조정액을 우선한다. 저장된 시작 잔액은 그 이전의 발생 원인을 증명하지 않으며, 저장된 순수납 조정액은 개별 수납 합계와 다를 수 있음을 명시한다.
- 다음 달 시작 잔액이 별도로 저장되어 있으면 현재 정산 잔액과의 차이를 별도 조정으로 표시한다. 자동 이월과 같은 것으로 설명하지 않는다.
- 과거에 실제 전달한 확정 안내본과의 연결은 구현하지 않았다. 따라서 차액을 ‘추가 수업’, ‘단가 변경’ 등의 원인으로 추정하지 않는다. 현재 확인한 수업 합계·납부·환불·잔액만 설명한다.
- 서울 기준 현재 월 이후이거나 미래 날짜 수업이 포함된 월은 잠정 안내다. 이후 수업·수납에 따라 바뀔 수 있음을 화면·출력·복사 문구에 남긴다. 과거 월도 현재 저장된 기록 기준이므로 과거 전달 안내서와 다를 수 있다.

시작 잔액의 연결 근거 누락, 미확인 단가, 수납 연결 오류, 수업 상세와 정산 합계 불일치가 있으면 정산 잔액을 `null`로 두고 확인 사유를 표시한다. 미확인을 0원으로 바꾸지 않으며 학부모 미리보기·이미지·PDF·설명 복사를 막는다. 근거 없는 빈 월도 출력 대상에서 제외한다.

## 조회 범위·권한·캐시

새 RPC는 `feecalc_monthly_history`이며 학생 ID와 월만 받는다. 기존 게이트웨이 인증 후 반포관 직원의 활성화된 인트라넷 수납 조회 권한(`readPayments`)을 다시 확인한다. 병합·별칭 학생, 잘못된 학생 ID·월, 잔액 문서의 학생 불일치를 거부한다.

학생 명부는 최대 5,000명, 정산 연결 기간은 최대 24개월이다. 화면에는 요청한 최근 3개월만 반환하되 자동 잔액을 연결하기 위해 필요한 과거 자료와 다음 달의 저장 시작 잔액을 읽는다. 클라이언트는 월별 수업 1,000건 초과, 중복 ID, 날짜·금액·정산 산식 오류도 거부한다.

서버 캐시는 한 요청 안에서 동일 문서·쿼리의 Promise를 공유하는 수준이다. 요청 사이에 권한이나 금융 자료를 재사용하지 않는다. `persistSnapshots:false`를 전달하며 원본·수납·계산 기록·정산 스냅샷에 쓰지 않는다. 이 릴리스에는 데이터 마이그레이션이 없다.

브라우저 캐시는 인증 세대·학생·조회 마지막 월을 키로 하는 메모리 캐시이며 유효기간은 60초, 최대 8개다. 같은 문맥의 진행 중 요청을 공유한다. 진입·학생 또는 조회 범위 변경·명시적 새로고침·파일 출력 시에 조회하며, 주기적인 백그라운드 조회는 없다. 상단 3개월 카드 이동은 추가 조회 없이 이미 받은 자료를 사용한다.

학생·월·로그인 문맥이 바뀌면 이전 비동기 응답을 버린다. 인증 변경 이벤트는 표시 자료·캐시·진행 중 요청 참조·미리보기를 지우고 학생을 다시 선택하게 한다. 캐시 유효기간 안의 화면 열람은 서버 권한 변경을 즉시 감지하지 않을 수 있으나, PNG/PDF 출력은 항상 서버에서 재인증·재조회한다.

## 학부모 출력과 최신성

일반 분량은 요약·과목별 합계·수업 달력을 한 장에 담는 기본 출력이다. `상세 근거 포함`은 기본 꺼짐이며 켜면 수업료와 납부·환불 표를 각각 최대 16행씩 추가한다. 분량이 많으면 기본 출력도 여러 장으로 이어지므로 한 장을 보장하지 않는다.

같은 날 수업을 `+N`으로 숨기거나 글자를 축소하지 않는다. 주 단위로 달력을 나누고, 한 날짜가 조밀하면 최대 4개씩 나눠 같은 주를 `계속`으로 이어 표시한다. 페이지마다 학생·월·조회 시각·쪽수를 남긴다. 20개 수업이 하루에 있는 합성 사례가 5페이지 PDF로 이어지는 것을 검증했다.

이미지는 페이지들을 간격을 두고 한 PNG로 묶는다. 전체 높이가 30,000px를 넘으면 PDF 사용을 안내한다. PDF는 브라우저에서 이미지를 A4 페이지에 배치하며 외부 변환 서비스에 학생 자료를 전송하지 않는다. 텍스트 검색용 PDF가 아니라 이미지 기반 PDF다. 페이지가 가독성을 유지할 수 있는 높이를 넘으면 파일 생성을 중단한다.

PNG/PDF 저장 직전 서버를 다시 조회해 지문을 비교한다. 원본이 달라졌으면 최신 자료를 다시 표시하고 확인 후 재출력하게 한다. 생성 도중 인증·학생·월·상세 포함 옵션이 바뀌어도 출력을 중단한다. 미리보기와 설명 복사는 현재 조회 자료를 사용하며 별도 강제 재조회는 하지 않는다. 조회 기준 시각으로 그 한계를 표시한다.

학부모 문서에는 내부 메모와 원본 기록 ID를 넣지 않는다. 학생·월·조회 시각·금액·수업 근거와 잠정 여부는 남긴다. 사용자 선택에 따라 파일을 내려받거나 설명을 복사할 뿐, 메신저 전송은 수행하지 않는다.

## 검증 기록과 재현

상위 작업의 완료 보고 기준으로 코어 6개, PDF 높이 제한 1개, 서버 8개, 프런트엔드 회귀 70개, 백엔드 회귀 32개로 총 117개 Node 테스트가 통과했다. 서버 검증은 현재 운영 소스에서 만든 정확한 배포 후보를 대상으로 했다. 문서 작성 과정에서 테스트를 재실행하거나 운영 학생 자료를 조회하지 않았다.

브라우저 검증은 외부 금융 엔드포인트를 차단하고 합성 인증·학생·수업·수납 응답을 사용했다. 데스크톱 1440×1000, 모바일 390×844, 과목 강조, 월 전환, PNG/PDF, 조밀한 날짜의 이어짐, 원본 변경 차단, 미확인·오류 상태, 늦은 응답 폐기, 학생·인증 변경, 원본 쓰기 없음 등을 확인했다. 실제 운영 학생으로 로그인한 종단 검증이나 학부모 메신저 수신 검증은 수행하지 않았다.

독립 마감 리뷰는 최초 3개 수정 사항이 해결된 뒤 출시 가능으로 판정했다. 일반 화면을 전체 검토한 뒤 변경 범위를 좁혀 최종 판정했다. 시각·출력 증거는 `.impeccable/review/monthly-history/`의 `desktop.png`, `mobile.png`, `parent-preview.png`, `parent.png`, `parent.pdf`, `dense-first.png`, `dense.pdf`다.

프로젝트 루트에서 실행한다. 브라우저 검증에는 Playwright를 찾을 수 있는 Node 환경과 테스트에 지정된 macOS Chrome이 필요하다.

```sh
node --test tests/monthly-history/core.test.cjs
node --test tests/monthly-history/pdf.test.cjs
FEE_HISTORY_SERVER_DIR=/tmp/feecalc-monthly-20261021/functions node --test tests/monthly-history/server.test.mjs
node --test tests/auth-gateway.test.mjs tests/calendar-core.test.cjs tests/financial-sources-core.test.cjs tests/progress-core.test.cjs
node tests/monthly-history/browser.cjs
```

백엔드 회귀는 기존 `feecalc-progress.test.mjs`·`feecalc-financial-sources.test.mjs`를 배포 후보의 `tests/`에 복사한 뒤, `/tmp/feecalc-monthly-20261021`에서 다음 명령으로 실행했다.

```sh
node --test tests/feecalc-progress.test.mjs tests/feecalc-financial-sources.test.mjs
```

이 명령의 서버 디렉터리는 검증된 배포 후보여야 한다. 기본값인 인접 프로젝트 소스를 운영 소스와 같다고 가정하지 않는다. 모듈 적용 명령은 새로 확보·검증한 배포 후보에만 실행한다.

```sh
node server/apply-monthly-history.mjs /tmp/feecalc-monthly-20261021/functions
```
