- 모드: **Preserve / targeted evolution**

- 영향 사용자: 이전 달 Access 수강료 표를 정리하는 반포관 데스크 실무자
- 핵심 업무: 원본 수업금·조정금·기납부금을 구분해 최종 미납/차액을 정확히 확인하고 안내서를 저장

## 브랜드·디자인 계약

- 권위 파일: 저장소의 `DESIGN.md`
- 기본 강조색: 에스에듀 블루 `#004094`
- 납부/차액 상태색: 기존 보라 계열
- 과목색: 기존 수학·국어·영어·과학·사탐 색 토큰과 `subj-*` 분류를 재사용
- 서체: 기존 Noto Sans KR/시스템 스택
- 숫자: 모든 단가·횟수·합계에 tabular numerals 유지
- 반경/깊이: 기존 8~12px 문서 패널과 얕은 경계·그림자 유지

## 정보 구조

- 전역 탭과 URL, `납부/차액` 명칭은 유지한다.
- 입력 흐름: Access 데이터 붙여넣기 → 분석 → 편집 표 확인 → 안내서 확인/저장.
- 기본 설정·저장 기록·안내서의 3열 PC 업무 구성을 유지한다.
- 안내서에서 과목별 수업, 이월/초과금, 기납부, 합계의 순서를 유지한다.

## 유지할 패턴

- 헤더 포함 붙여넣기와 자동 분류
- 분석 뒤 행 단위 수정 및 삭제
- 과목별 2열 안내서 구성
- 수업·조정·납부의 독립 합산
- 서버 저장본과 원문 보관

## 고칠 패턴

- 기호가 붙은 헤더를 인식하지 못해 다른 숫자 열을 금액으로 오인하는 fallback
- 금액이 빈 수업 행을 수강료로 포함하는 거짓 성공
- `개 수업`이 수업 횟수가 아니라 행 개수로 읽히는 모호한 표현
- 과목 카드가 모두 흰색이라 많은 과목을 빠르게 구별하기 어려운 상태
- 시간·회당 단가·횟수의 계산 근거가 안내서에서 한 번에 읽히지 않는 상태
- 원본 합계와 계산 합계의 일치 여부를 확인할 방법이 없는 상태

## 제공 이미지 적용 범위

- Authority: **approved implementation reference for the named payment calculation**
- Implement: Access 열의 의미, 원본 합계 5,062,292원, 회당·횟수·금액의 관계
- Adapt: 기존 앱 색·서체·카드·반응형·접근성
- Ignore: 스프레드시트 자체의 회색 표 스타일, 빈 할인 열, 앱에 없는 장식

## 시각 방향 읽기

- 기존 화면은 고밀도 실무 UI이며 장식보다 비교 가능성이 중요하다.
- 모션은 거의 없고 상태 전환만 160ms로 제한되어 있다.
- 과목 카드 5개 이상을 한 화면에서 비교하므로 색은 장식이 아니라 탐색 단서다.
- 전체 재디자인보다 계산 근거의 정보 계층과 과목별 표면색을 정리하는 편이 적합하다.
