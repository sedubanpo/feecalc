# 납부/차액 계산 UX 계약

## 결정

`■금액`을 수업금의 권위 열로 사용하고, 해당 셀이 비어 있으면 행을 합계에서 제외한다. 원본 마지막 합계는 별도 검증값으로 보존하며 계산 결과와 일치 여부를 표시한다.

- 대상 사용자/업무/화면: 데스크 실무자 / 전월 정산 / Chrome 기반 납부·차액 탭
- 권위: 사용자 제공 Access 표, 기존 `DESIGN.md`, 현재 저장·편집 흐름
- 대안 1: 빈 금액을 `회당 × 횟수`로 다시 계산 — Access가 이미 확정한 금액과 어긋날 수 있어 제외
- 대안 2: 마지막 합계만 그대로 표시 — 행 편집 결과와 모순될 수 있어 제외
- 선택 근거: 확정 금액 열을 합산하면서 원본 합계와 편집 후 합계를 동시에 대조할 수 있음
- 제한: 헤더가 전혀 없는 임의 텍스트는 보수적 fallback을 사용하며 원본 합계 검증은 제공하지 못할 수 있음

## 여정과 상태

1. 사용자가 헤더와 합계 행을 포함한 Access 데이터를 붙여넣는다.
2. 분석기는 수업·조정·납부 행을 분류하고, 금액 없는 수업 행을 `미산정`으로 제외한다.
3. 편집 표는 각 수업의 회당 단가, 횟수, 1회당 시간을 읽기 전용 산출 기준으로 보여준다.
4. 안내서는 과목별 색상으로 묶고 `회당 × 횟수 · 1회당 시간`을 표시한다.
5. 계산 합계와 Access 원본 합계가 같으면 일치 상태를, 다르면 차액과 재검토 상태를 표시한다.
6. 사용자가 금액·할인·분류를 수정하면 계산 합계와 검증 상태가 즉시 갱신된다.

## 불변식

- 수업료 합계에는 `■금액`이 0보다 큰 수업 행만 포함한다.
- 회당 단가나 시간 값은 표시 근거이며 `■금액`을 대체하지 않는다.
- 납부금액은 절댓값으로 보관하되 최종 합계에서는 차감한다.
- 초과금은 더하고 이월금은 뺀다.
- 최종값 = 수업료 - 행 할인 - 퍼센트 할인 + 조정 - 기납부.
- 제공 fixture의 결과는 정확히 5,062,292원이어야 한다.
- 저장본을 다시 열어도 단가·횟수·시간·원본 합계가 유지되어야 한다.
- 다른 계산 탭과 Supabase RPC 계약은 변경하지 않는다.

## 공간 계약

- 편집 표는 기존 위치와 스크롤 소유권을 유지한다.
- 새 `산출 기준` 열은 편집 표 안에서만 보이며 좁은 폭에서는 표의 가로 스크롤로 접근한다.
- 안내서의 과목 카드는 2열을 유지하고, 좁은 안내서 폭에서는 기존 문서 폭 안에서 줄바꿈한다.
- 과목 카드의 의미 순서는 과목명 → 합계/횟수 → 수업별 산출 기준 → 금액이다.
- 원본 합계 대조는 최종 합계 바로 위에 두어 계산 결과와 관계가 유지되게 한다.

## 접근성·입력

- 새 상태는 색상만으로 전달하지 않고 `일치`, `차이`, `원본 합계 없음` 텍스트를 함께 쓴다.
- 삭제는 실제 button과 접근 가능한 이름을 사용한다.
- 수치 열은 tabular numerals를 사용한다.
- 기존 키보드 포커스와 40px 최소 클릭 영역을 유지한다.
- 한국어 단일 로케일 정책을 유지한다.

## 개인정보 경계

- 사용자 제공 학생명과 실제 금액은 기능 재현에만 사용한다.
- 새 시각 증빙은 실제 학생명을 저장하지 않고 `검증학생` fixture로 캡처한다.
