# Calculator session and functional audit — 2026-10-11

## Findings and changes

- The deployed calculator API already used Intranet's monthly fee projection, including session pricing, but returned every source fragment as an independent lesson. Continuous 1h + 1h records therefore still became two calculator occurrences/templates/cards. The API now uses Intranet's `displayedLessonSessions` result and consolidates homogeneous-attendance sessions into one 2h occurrence, summing the already-projected charges exactly once. Mixed attendance, explicit separation, gaps and different teachers remain separate. Unknown charges remain unknown.
- Responses retain immutable source segments and stable session IDs. When a saved draft refers to an old fragment ID (including prior-month basis, manual dates, forecast exclusions or edits), the calculator retains that session's fragments so local customizations do not silently disappear. Explicit fresh reload uses the merged session.
- The progress UI repeatedly calculated the same state during one refresh. A single-entry cache keyed by the complete state and academy date reuses results and invalidates after any input/identity/date change. The API also skips its second normal-attendance projection when there are no absence rows.
- The long-teacher mobile regression found labels exceeding calendar cell width. Names of up to six characters remain unbroken; longer labels can wrap inside the cell.
